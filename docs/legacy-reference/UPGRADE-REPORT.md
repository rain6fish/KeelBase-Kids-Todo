## 二、关键问题修复对照

### P0 安全（5/5 关闭）

| # | 问题 | 处置 |
|---|------|------|
| 1 | WebSocket 无认证、CORS 全开 | 强制 JWT 校验，身份仅取自 token；频道白名单；CORS 从 `CORS_ORIGINS` 白名单读取，生产拒绝 `*` |
| 2 | 奖励兑换无角色检查 | 家长校验 + 受益人须为本家庭孩子；并发双花风险仍在（见遗留项） |
| 3 | 手机号明文存储 | AES-256-GCM transformer 加密 + `phone_hash` 唯一索引（因随机 IV 无法对密文建唯一索引）；全局响应脱敏为 `138****5678` |
| 4 | SMS 验证码 Mock | Redis 原子比对（Lua GET+DEL）、一次性消费、5 次错误作废、60 秒冷却 + 每日上限 |
| 5 | Sync Push 绕过业务校验 | 改走 `TaskService`，复用状态机与权限；字段白名单；批量上限 100 |

## 四、遗留风险与下一步

### 上线前必须处理（阻断项）

1. **存量数据迁移**：新增 `phone_hash` 后必须执行回填脚本，否则老用户无法按手机号登录；迁移 `20261103000001-BusinessLogicGaps`、`20261103000002-ComplianceFeatures` 须在生产显式执行（当前仅开发 `synchronize` 自动建表）。
2. **密钥管理**：`PHONE_ENCRYPTION_KEY` 须由密钥管理系统注入；当前 `.env` 为开发值。建议引入密钥版本号以支持轮换。
3. **真实环境联调**：本环境无 PostgreSQL/Redis，Cron 触发、迁移执行、WebSocket 握手均未在真实库验证，需在 staging 跑一轮端到端。
4. **HTTP 直建任务不写 change_sequence**：仅 sync push 创建的任务会回流，跨端一致性依赖全量拉取兜底。

### 应在验证期解决（非阻断）

5. 注销账号 7 天后物理删除的定时任务未实现（字段与审计已预留）。
6. 积分扣减/退款缺行级锁，并发下有双花与重复退款风险。
7. 通知 `sendToFamily` 广播路径不落库，家庭级历史通知缺失。
8. `GET /sync/pull` 端点不存在，客户端靠 404 降级到 `/sync/changes`。
9. 移动端仍有 39 条 lint info（print、命名规范），建议统一接入日志框架后清理。
10. Web 端 chunk 体积偏大（element-plus + echarts），可做路由级懒加载与按需引入。

### 产品决策待确认

- 后端已实现「审批模式」「积分商城/奖励兑换」，但 MVP v2 将其列为 Out of scope。**建议 UI 保持关闭**，等真实家庭试用后再决定开放，避免第一版增加孩子操作摩擦。
- 超时提醒已实现给孩子的温和提示，与 MVP v2 的 N3「不做超时施压推送」有张力，建议第一周关闭该通道，仅推家长。

## 五、结论

**代码侧从「不可上线的原型」提升到「可进入 staging 联调」的状态**：5 个 P0 安全漏洞全部关闭，核心链路（注册 → 家庭 → 孩子 PIN 登录 → 任务 → 完成 → 打卡）三端已打通，测试用例从 62 增至 117。

但产品判断不变：**下一步不是继续加功能，而是把这条链路交给 10 个真实家庭**。按 MVP-v2-PRD 第 4 章指标验收——北极星「孩子次周留存 ≥ 40%」，低于 25% 则回到用户访谈重新定位，而不是继续写代码。
