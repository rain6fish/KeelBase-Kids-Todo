# MVP v2 产品需求清单：「小计划」

> 版本：v2.0 | 日期：2026-11-03 | 上游文档：kids-todo-prd.md、REVIEW-v2.md
> 定位调整：从「儿童自主规划工具」收缩为「**家长逐步放权的亲子学习协作工具**」，v1 只服务 6-10 岁小学生家庭

---

## 0. 本版本的核心目标（唯一目标）

**在 10 个真实家庭中验证：孩子是否愿意在无人催促的情况下，连续两周打开并完成任务。**

不为验证目标服务的一律不做。本版不追求功能完整度，只追求「一条链路真正跑通」。

---

## 1. 范围界定

### 1.1 做（In Scope）

| 模块 | 内容 | 端 |
|------|------|-----|
| 账号与家庭 | 家长手机号注册/登录；创建家庭；邀请码；孩子 PIN 登录 | 家长：Web；孩子：Android |
| 任务核心 | 创建/编辑/完成/取消/删除；分类标签；优先级；计划时间段 | 双端 |
| 今日视图 | 日视图时间线 + 灵活任务区 + 完成进度 | 双端 |
| 任务备注 | 单条文字备注，显示作者与时间 | 双端 |
| 操作流水 | 全局 + 按任务查看，不可删除篡改 | Web 优先 |
| 最简激励 | 连续打卡天数 + 完成任务星星动画 + 打卡日历 | 双端（孩子端视觉为主） |
| 通知 | 家长备注 → 孩子端站内通知；孩子完成 → 家长端站内通知 | 双端 |
| 合规 | 监护人同意、隐私说明、数据导出、账号注销 | 双端 |

### 1.2 明确不做（Out of Scope，写入合同级边界）

- ❌ 离线同步与冲突解决（改为"无网时只读缓存 + 明确提示"）
- ❌ 周视图 / 月视图 / 日历视图
- ❌ 审批模式（保留数据库字段，UI 不开放）
- ❌ 积分商城与奖励兑换
- ❌ 语音备注、图片备注
- ❌ 多孩子支持（数据模型预留 `assignee_id`，UI 不开放）
- ❌ 家长间 @mention
- ❌ 使用时段锁定（防沉迷）
- ❌ iOS 客户端
- ❌ 微服务拆分（单体 + 模块化，禁止在架构图中出现服务拆分）

> 任何新增需求进入本版，必须同时移除一项同等成本的需求。无例外。

## 2. 用户与角色

| 角色 | 设备 | 核心诉求 | 关键约束 |
|------|------|---------|---------|
| 家长 A（主账号） | Web（PC/平板） | 布置任务、了解进展、给反馈 | 手机号注册，家庭 owner |
| 家长 B（协同） | Web | 同上，与 A 平级 | 邀请码加入，需短信验证 |
| 孩子 | Android App | 知道今天做什么、完成后有成就感 | PIN 登录，无手机号，无社交 |

**产品红线**：孩子端不出现「监控」「家长已查看」等施压性文案；不出现红黄绿优先级色块对孩子形成压迫感（孩子端用中性色 + 图标区分）。

## 3. 功能需求与验收标准

### 3.1 账号与家庭（P0）

| 编号 | 需求 | 验收标准 |
|------|------|---------|
| A1 | 家长手机号注册 | 短信验证码必须与 Redis 中存储值比对，错误/过期/已使用均拒绝；手机号唯一索引；存储加密 |
| A2 | 手机号登录 + Token 刷新 | 刷新失败自动登出并跳转登录页；并发 401 只触发一次刷新 |
| A3 | 创建家庭 | 生成 6 位大写字母+数字邀请码，全局唯一，7 天有效；全项目仅一处生成算法 |
| A4 | 家长 B 加入家庭 | 邀请码 + 短信验证码双校验；一个家庭最多 2 个家长，超出明确报错 |
| A5 | 孩子 PIN 登录 | 家长在家庭设置中创建孩子档案（昵称、头像、4 位 PIN）；孩子端选择头像 → 输入 PIN → 进入；**不得存在任何硬编码 ID** |
| A6 | 监护人同意 | 注册流程中必须勾选《儿童个人信息处理规则》并记录同意时间、版本号；未同意不可创建孩子档案 |

### 3.2 任务核心（P0）

| 编号 | 需求 | 验收标准 |
|------|------|---------|
| T1 | 创建任务 | 标题必填（1-50 字）；分类从预置标签选；计划时间段可选；优先级 高/中/低 |
| T2 | 状态流转 | `待开始 → 进行中 → 已完成`；`待开始/进行中 → 已取消`（需填原因，可空）；非法转换返回明确错误码；服务端状态机为唯一权威 |
| T3 | 完成与打卡 | 孩子标记完成 → 立即反馈星星动画 + 当日进度更新 → 打卡天数 +1（当日全部任务完成时） |
| T4 | 编辑与删除 | 创建人可编辑自己的任务；家长可编辑/删除全部；孩子可删除自己创建的任务；软删除，30 天内可恢复，恢复保留原状态 |
| T5 | 重复任务 | 支持每日/每周重复；由定时任务在每日 00:05 生成当日实例；生成失败有告警日志；同一模板同一天不重复生成 |
| T6 | 相似标题提示 | 创建时若当日已有相似标题（编辑距离阈值），返回提示但不阻断 |
| T7 | 角色化 UI | 孩子端不显示「高优先级」选项；孩子端不显示「删除他人任务」入口；所有权限判断在 UI 与 API 双层生效 |

### 3.3 今日视图与激励（P0）

| 编号 | 需求 | 验收标准 |
|------|------|---------|
| V1 | 日视图 | 按计划时间排序；无时间任务进入「灵活任务」区；进行中任务高亮；顶部进度条 `已完成/总数` |
| V2 | 打卡日历 | 月历展示，完成任务的日子显示星星；连续天数在顶部常驻展示 |
| V3 | 完成反馈 | 完成任务的 0.8s 内出现动效；连续 3/7/14 天有阶段性庆祝（轻量，不打断） |

### 3.4 备注与通知（P1）

| 编号 | 需求 | 验收标准 |
|------|------|---------|
| N1 | 任务备注 | 文字，≤200 字，显示作者头像+昵称+相对时间；作者可编辑/删除自己的备注，家长可删除任意备注 |
| N2 | 站内通知 | 家长备注 → 孩子端收到；孩子完成 → 家长端收到；通知中心可拉取历史（非仅实时推送） |
| N3 | 通知克制度 | 孩子端每日通知上限 5 条；不做"任务超时提醒"给孩子的施压推送 |

### 3.5 操作流水（P1）

| 编号 | 需求 | 验收标准 |
|------|------|---------|
| L1 | 全量记录 | 创建/编辑/状态变更/删除/恢复/备注增删/审批类操作全部落库，含操作人、时间、字段级 before→after |
| L2 | 查询 | 全局倒序 + 按任务查看 + 按人筛选 + 按日期筛选 |
| L3 | 不可篡改 | 数据库层禁止 UPDATE/DELETE（触发器）；API 无写接口 |
| L4 | 数据隔离 | 家长仅见本家庭；孩子仅见与自己相关任务的流水 |

### 3.6 合规与安全（P0，发布门禁）

| 编号 | 需求 | 验收标准 |
|------|------|---------|
| C1 | 数据最小化 | 孩子档案仅采集昵称、头像、PIN 哈希；不采集真实姓名、生日、学校、位置 |
| C2 | 手机号加密 | 存储 AES-256-GCM；查询前加密；密钥从环境变量注入，不落代码库 |
| C3 | 传输与通道安全 | 全站 HTTPS；WebSocket 必须 JWT 鉴权，CORS 白名单限定域名 |
| C4 | 权限隔离 | 所有资源查询强制带 `family_id` 条件；跨家庭访问返回 404 而非 403（避免探测） |
| C5 | 数据导出 | 家长可导出本家庭全部数据为 JSON（含任务、备注、流水） |
| C6 | 账号注销 | 注销后 7 天内可撤回，超期彻底删除；删除范围覆盖所有关联表与备份标记 |
| C7 | 无广告无外链 | 孩子端无任何第三方 SDK（除崩溃统计）、无跳转外链 |

## 4. 度量指标（本版必须埋点）

| 指标 | 定义 | 目标值 | 用途 |
|------|------|--------|------|
| 激活率 | 完成「建家庭 + 建首个任务 + 孩子首次登录」的家庭 / 注册家庭 | ≥ 70% | 验证引导链路 |
| 孩子次周留存 | 第 2 周仍有 ≥3 天打开的孩子 / 首周激活孩子 | ≥ 40% | **北极星** |
| 自主创建占比 | 孩子自己创建的任务 / 全部任务 | ≥ 20% | 验证"自主"定位是否成立 |
| 任务完成率 | 已完成 / 当日应完成 | ≥ 65% | 验证任务量是否合理 |
| 家长互动 | 每家庭每周备注条数 | ≥ 3 | 验证协作价值 |
| 首次价值时长 | 注册到孩子完成第一个任务的中位时长 | ≤ 10 分钟 | 验证冷启动摩擦 |

> 若次周留存 < 25%，不进入下一阶段开发，回到用户访谈重新定位。

## 5. 交付节奏

| 阶段 | 周期 | 交付物 | 出口条件 |
|------|------|--------|---------|
| S1 止血与合规 | 1 周 | P0 安全修复、监护人同意、假成功清理 | 安全自检 0 项 P0；合规三件套可用 |
| S2 链路闭合 | 2 周 | 注册→家庭→PIN→任务→完成→打卡全通 | 端到端用例通过；无 Mock 残留 |
| S3 真实验证 | 2 周 | 10 个家庭封闭试用 | 指标达标（见第 4 章） |
| S4 决策 | — | 留存数据评审 | 决定是否投入激励 2.0 / 离线 / 周视图 |

## 6. 需求变更规则

1. 本版范围冻结，新增需求一律进入 Backlog，不插队。
2. 唯一例外：影响儿童数据安全或阻断核心链路的问题，可即时插入。
3. 每个需求必须有可验证的验收标准，无验收标准的需求不予开发。
4. 所有 Mock 必须登记（位置、owner、拆除期限），无主 Mock 视为缺陷。
